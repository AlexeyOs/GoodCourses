# ADR-0004: Koyeb Free для приложения и Neon Free для PostgreSQL

- Статус: принято
- Дата: 2026-11-09
- Уточняет: [ADR-0001](0001-production-hosting-and-database.md)
- Связанный SDD: [безопасное развёртывание GoodCourses](../specifications/issue-65-production-deployment.md)

## Контекст

ADR-0001 зафиксировал платформонезависимый Docker-образ приложения и отдельную PostgreSQL в Neon, но намеренно не выбрал поставщика вычислительных ресурсов. Для первого публичного стенда GoodCourses нужен конкретный хостинг с минимальной стоимостью, автоматическим HTTPS, секретами, логами и развёртыванием Docker-контейнера.

Стенд предназначен для владельца проекта и небольшой группы знакомых. Для него допустимы холодный старт, ограниченная производительность и отсутствие SLA, но недопустимы потеря постоянных данных, хранение секретов в Git и неконтролируемые расходы.

На дату решения Koyeb предоставляет одной организации один бесплатный Web Service с 512 МБ RAM, 0,1 vCPU и 2 ГБ SSD. Бесплатный экземпляр доступен во Франкфурте или Вашингтоне, не поддерживает подключаемые постоянные тома и масштабируется до нуля после часа без входящего трафика. Условия бесплатного тарифа могут измениться и проверяются перед развёртыванием.

## Рассмотренные варианты

### Koyeb Free и Neon Free

Плюсы:

- один бесплатный Web Service не тарифицируется;
- поддерживаются Dockerfile, автоматический HTTPS, secrets, логи и развёртывание из Git;
- база отделена от жизненного цикла контейнера;
- при смене compute-провайдера перенос базы не требуется.

Минусы:

- 512 МБ RAM и 0,1 vCPU оставляют небольшой запас для JVM, Tomcat, Spring и Hibernate;
- после простоя возможен холодный старт;
- файловая система экземпляра непостоянна;
- бесплатный тариф не имеет SLA и ограничен одним экземпляром;
- для регистрации Koyeb может потребовать банковскую карту и временную авторизацию средств; необходимо явно выбрать Starter и только экземпляр типа `free`.

### Google Cloud Run и Neon Free

Плюсы: зрелое автоматическое масштабирование, настраиваемые ресурсы и оплата по факту использования. Минусы: требуется биллинговый аккаунт, а ошибочная конфигурация или нежелательный трафик могут создать расходы; для первого стенда потребуются дополнительные финансовые ограничения.

### Heroku Eco и Neon Free

Плюсы: проект ранее работал на Heroku, а ежемесячная стоимость compute предсказуема. Минус: бесплатного dyno больше нет; минимальный Eco-тариф платный.

### Render Free и Neon Free

Плюс: простое Docker-развёртывание. Минусы: доступной бесплатному экземпляру памяти недостаточно для надёжного запуска текущего Java-приложения, а ограничения исходящего SMTP мешают восстановлению пароля через обычный почтовый сервер.

### Собственный VPS

Плюсы: полный контроль и предсказуемые ресурсы. Минусы: постоянная стоимость и необходимость самостоятельно сопровождать ОС, Docker, TLS, firewall, обновления и резервное восстановление.

## Решение

Первый публичный стенд GoodCourses разворачивается как один Web Service типа `free` в Koyeb. Приложение собирается существующим платформонезависимым Dockerfile и остаётся stateless.

Постоянные данные размещаются в отдельном проекте Neon Free. `DATABASE_URL` передаётся только через secrets Koyeb, подключение использует TLS с проверкой имени хоста. Flyway применяет версионированные миграции при запуске согласно ADR-0002. База Koyeb не используется из-за малого лимита активного времени и чтобы сохранить независимость данных от compute-провайдера.

Локальные 2 ГБ Koyeb считаются временными. В контейнере разрешены только временные файлы и потоковые логи. Пользователи, курсы, отзывы, профили и другие постоянные данные хранятся в Neon. Если появятся пользовательские загрузки, для них выбирается отдельное объектное хранилище новым решением.

Для работы в лимите 512 МБ до публикации измеряется фактическое потребление памяти. JVM получает явные ограничения heap и metaspace, пул соединений с Neon и число рабочих потоков Tomcat уменьшаются. Конкретные значения определяются нагрузочной проверкой и фиксируются в инструкции развёртывания, а не в ADR.

Koyeb использует `/health/ready` для проверки готовности. `/health/live` остаётся проверкой процесса без обращения к БД. Секреты, пароли и `DATABASE_URL` не записываются в репозиторий, Docker image и логи.

Для исключения случайных расходов организация остаётся на Starter, создаётся только один экземпляр типа `free`, а платные экземпляры, базы, volumes и дополнительные сервисы не включаются. После регистрации проверяются выбранный план и раздел Usage and billing.

## Последствия

Положительные:

- первый публичный стенд может работать без ежемесячной платы за compute и PostgreSQL;
- перезапуск, пересборка и scale-to-zero Koyeb не удаляют данные Neon;
- сохраняется возможность перенести контейнер на Cloud Run, Heroku, Render или VPS;
- стоимость не растёт от нагрузки, пока используется только экземпляр Koyeb типа `free` и Neon остаётся на Free.

Отрицательные:

- первый запрос после простоя может выполняться заметно дольше;
- приложение может не уложиться в 512 МБ или запускаться неприемлемо долго на 0,1 vCPU;
- при недоступности Koyeb или Neon сервис не имеет автоматического резервного экземпляра;
- бесплатные тарифы могут быть изменены или прекращены;
- данные Neon требуют отдельной проверки резервного восстановления.

## Проверка решения

Перед признанием стенда готовым необходимо:

1. Собрать и запустить production image с лимитом памяти 512 МБ.
2. Проверить успешное применение Flyway на пустой тестовой базе Neon.
3. Измерить холодный старт и пиковое потребление памяти.
4. Проверить `/health/live` и `/health/ready`.
5. Выполнить регистрацию, вход, восстановление пароля, работу с курсами и отзывами.
6. Перезапустить и повторно развернуть контейнер, подтвердив сохранность данных в Neon.
7. Проверить отсутствие секретов в Git, image и логах.
8. Убедиться в панели Koyeb, что используется Starter и ровно один экземпляр типа `free`.

## Условия пересмотра

Решение пересматривается, если:

- приложение не укладывается в 512 МБ после обоснованной настройки JVM;
- холодный старт или 0,1 vCPU делают основные сценарии неприемлемыми;
- бесплатные лимиты Koyeb или Neon меняются;
- требуется постоянное хранение файлов;
- появляется требование SLA, резервирования или постоянной доступности;
- аудит безопасности требует WAF, частной сети или фиксированного региона;
- нагрузка небольшой группы пользователей перерастает возможности бесплатного стенда.

Предпочтительный следующий вариант при нехватке ресурсов выбирается по фактическим измерениям: платный Koyeb/Heroku для предсказуемой стоимости либо Cloud Run с жёсткими финансовыми ограничениями. Neon остаётся основной базой, пока её лимиты и надёжность удовлетворяют требованиям.
