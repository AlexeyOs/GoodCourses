# ADR-0001: платформонезависимый контейнер и Neon PostgreSQL

- Статус: принято
- Дата: 2026-11-02
- Связанный issue: [#65](https://github.com/AlexeyOs/GoodCourses/issues/65)
- Связанный SDD: [безопасное развёртывание GoodCourses](../specifications/issue-65-production-deployment.md)

## Контекст

GoodCourses нужен публичный стенд для небольшой группы пользователей с минимальной стоимостью. Приложение является WAR для Tomcat 9, а постоянные данные хранятся в PostgreSQL. Условия бесплатных тарифов меняются, поэтому жёсткая зависимость от API одного хостинга увеличит стоимость переноса.

## Рассмотренные варианты

### Один поставщик для приложения и PostgreSQL

Плюсы: единая панель и простая сеть. Минусы: бесплатные базы часто имеют короткий срок жизни или жёсткие ограничения; перенос сложнее.

### Docker-хостинг и отдельный Neon PostgreSQL

Плюсы: постоянная PostgreSQL-база, переносимый образ приложения, возможность заменить хостинг без переноса данных. Минусы: два сервиса, внешнее TLS-соединение и отдельные настройки секретов.

### VPS

Плюсы: полный контроль и предсказуемая среда. Минусы: постоянная стоимость, ручное администрирование, обновления безопасности и backup.

## Решение

Приложение поставляется как платформонезависимый Docker-образ, а PostgreSQL размещается в Neon. Контейнер не использует vendor-specific SDK и получает конфигурацию через переменные окружения.

Конкретный Docker-хостинг пока не фиксируется. Render, Koyeb или другой кандидат выбирается после пробного развёртывания по критериям SDD: Dockerfile, HTTPS, secrets, health-check, логи, стоимость, холодный старт и rollback.

Neon подключается только по TLS. Приложение остаётся stateless; постоянные пользовательские данные не записываются в файловую систему контейнера.

Соединение с Neon проверяет сертификат и имя хоста (`sslmode=verify-full` либо эквивалент). Разбор `DATABASE_URL` обязан сохранять query-параметры и завершать запуск при некорректной или небезопасной конфигурации. Перед публикацией закрепляются patch-версии runtime-образа и выполняются dependency/image security scans.

## Последствия

Положительные:

- хостинг приложения можно заменить без миграции основной БД;
- локальный и production-запуск используют один образ;
- стоимость первого стенда может быть близкой к нулю;
- секреты не попадают в образ.

Отрицательные:

- доступность зависит от двух внешних сервисов;
- бесплатный compute может засыпать и давать холодный старт;
- внешний PostgreSQL требует корректных TLS, таймаутов и небольшого пула;
- условия тарифов нужно периодически перепроверять.

## Условия пересмотра

Решение пересматривается, если:

- бесплатный или недорогой Docker-хостинг не обеспечивает приемлемый запуск Tomcat;
- задержка или лимиты Neon мешают пользовательским сценариям;
- появляется необходимость хранить пользовательские файлы;
- стоимость двух сервисов превышает стоимость управляемого VPS;
- требования требуют регионального размещения или повышенной доступности.

После пробного развёртывания конкретный провайдер и измеренные ограничения фиксируются новым ADR, который дополняет или заменяет это решение. Принятый ADR задним числом не переписывается.
