# SDD: оценка курса по пятибалльной шкале

- Issue: [#31 — Add mark for course by five-point scale](https://github.com/AlexeyOs/GoodCourses/issues/31)
- Статус: проект решения
- Тип документа: Software Design Description
- Связанная функция: отзывы о курсах

## 1. Цель

Добавить к пользовательскому отзыву оценку курса целым числом от 1 до 5. Пользователь должен указывать оценку при создании нового отзыва, видеть её на странице курса и в разделе «Мои отзывы», а также изменять вместе с текстом собственного отзыва.

На странице курса необходимо показывать среднюю оценку и количество учтённых оценок.

## 2. Текущее состояние

В проекте уже существуют:

- JPA-сущность `FeedBack`, связанная с `Profile` и `Course`;
- создание, просмотр, редактирование и удаление отзывов;
- правило «один пользователь — один отзыв на курс»;
- nullable-колонка `feedback.rating integer` в SQL-схеме.

При этом поле `rating` отсутствует в Java-модели, DTO формы, сервисах и интерфейсе. В базе нет ограничения диапазона значений.

## 3. Архитектурное решение

Оценка хранится в записи `feedback`, а не в отдельной таблице. Отзыв уже является уникальным мнением пользователя о конкретном курсе, поэтому отдельная сущность оценки усложнила бы согласование текста и оценки без дополнительной пользы.

Средняя оценка не хранится в `course`. Она вычисляется запросом по актуальным отзывам. Это исключает рассинхронизацию агрегата после создания, изменения или удаления отзыва.

Отдельный ADR не требуется: решение локально, обратимо и фиксируется данным SDD.

## 4. Бизнес-правила

1. Оценка является целым числом от 1 до 5 включительно.
2. Для нового отзыва оценка обязательна.
3. Один пользователь выставляет курсу не более одной оценки, поскольку может иметь только один отзыв на курс.
4. Владелец может изменить оценку только собственного отзыва.
5. При изменении текста или оценки обновляется `lastUpdate`.
6. После удаления отзыва его оценка перестаёт участвовать в агрегате курса.
7. Старые отзывы с `rating IS NULL` сохраняются и отображаются как «Без оценки» до редактирования.
8. При сохранении старого отзыва через форму пользователь должен выбрать оценку.
9. Среднее значение вычисляется только по ненулевым оценкам.
10. При отсутствии оценок среднее не подменяется нулём; интерфейс показывает «Оценок пока нет».

## 5. Модель данных

### 5.1. JPA

В `FeedBack` добавляется поле:

```java
@Column(name = "rating")
private Integer rating;
```

Используется `Integer`, а не `int`, чтобы приложение могло прочитать существующие отзывы с `NULL`.

### 5.2. Форма

В `FeedbackForm` добавляется:

```java
@NotNull(message = "Выберите оценку")
@Min(value = 1, message = "Оценка должна быть от 1 до 5")
@Max(value = 5, message = "Оценка должна быть от 1 до 5")
private Integer rating;
```

Контроллер не принимает отдельное доверенное значение оценки вне валидируемого DTO. Сервис повторно проверяет диапазон, поскольку может вызываться не только из MVC-контроллера.

### 5.3. PostgreSQL

Колонка уже существует и остаётся nullable для совместимости со старыми отзывами. Добавляется ограничение:

```sql
ALTER TABLE feedback
    ADD CONSTRAINT chk_feedback_rating
    CHECK (rating IS NULL OR rating BETWEEN 1 AND 5);
```

Перед миграцией выполняется диагностика:

```sql
SELECT id, rating
FROM feedback
WHERE rating IS NOT NULL
  AND rating NOT BETWEEN 1 AND 5;
```

Если найдены некорректные значения, миграция останавливается. Автоматически исправлять или удалять такие данные нельзя.

## 6. Агрегация рейтинга

Репозиторий должен возвращать среднее значение и количество ненулевых оценок для курса. Допустимы:

- один projection-запрос с `AVG` и `COUNT`;
- два агрегатных запроса, если это лучше соответствует существующему стилю проекта.

Предпочтителен один запрос:

```sql
SELECT AVG(f.rating), COUNT(f.rating)
FROM feedback f
WHERE f.course_id = :courseId
  AND f.rating IS NOT NULL;
```

Результат передаётся в представление через отдельный DTO, например `CourseRatingSummary`, содержащий:

- `average`;
- `count`.

Округление выполняется только для отображения до одного знака после запятой. В вычислениях сохраняется точное значение.

## 7. Изменения приложения

### 7.1. Service

`FeedbackService.create` и `FeedbackService.update`:

- проверяют наличие оценки;
- проверяют диапазон `1..5`;
- сохраняют оценку вместе с текстом;
- не принимают владельца из HTTP-формы;
- сохраняют существующую проверку владельца по `feedbackId + profileId`.

Сервис чтения курса получает агрегат рейтинга через репозиторий или отдельный сервис без вычисления среднего в контроллере.

### 7.2. Controller

Контроллеры продолжают использовать существующие маршруты:

- `POST /add/feedback`;
- `POST /my-reviews/{id}/edit`.

При ошибке оценки форма отображается повторно с сохранёнными текстом и выбранным значением. После успешного POST применяется redirect.

### 7.3. Интерфейс

Формы создания и редактирования содержат доступный элемент выбора с пятью значениями. Базовый вариант — обычный `<select>`, работающий без JavaScript:

```text
Выберите оценку
1 — Очень плохо
2 — Плохо
3 — Нормально
4 — Хорошо
5 — Отлично
```

Звёзды могут использоваться как дополнительное визуальное представление, но не должны быть единственным элементом управления.

Отображение:

- на странице курса — средняя оценка и количество оценок;
- рядом с каждым отзывом — индивидуальная оценка или «Без оценки»;
- в «Моих отзывах» — индивидуальная оценка;
- в форме редактирования — текущее значение, если оно существует.

Все ссылки учитывают `pageContext.request.contextPath`. Текст отзыва продолжает выводиться с экранированием.

## 8. Безопасность и целостность

- Значение из формы считается недоверенным.
- HTML-ограничения не заменяют серверную валидацию.
- PostgreSQL `CHECK` является окончательной защитой диапазона.
- Изменение оценки выполняется только после проверки владельца отзыва.
- `profileId` не передаётся через форму как доказательство владельца.
- Нельзя ослаблять Spring Security или CSRF ради реализации рейтинга.
- Ошибка ограничения БД не должна раскрывать stack trace пользователю.

## 9. Критерии приёмки

1. Авторизованный пользователь может создать отзыв с оценкой от 1 до 5.
2. Отзыв без оценки не создаётся.
3. Значения меньше 1, больше 5, дробные и нечисловые значения не сохраняются.
4. Оценка сохраняется в `feedback.rating` и загружается через JPA.
5. Пользователь видит собственную оценку в «Моих отзывах».
6. Оценка отображается рядом с отзывом на странице курса.
7. Владелец может изменить оценку, после чего обновляется `lastUpdate`.
8. Другой пользователь не может изменить оценку подстановкой ID.
9. После удаления отзыва его оценка не участвует в среднем курса.
10. Среднее и количество оценок корректно обновляются после создания, изменения и удаления.
11. Старый отзыв с `NULL rating` открывается без ошибки и отображается как «Без оценки».
12. При редактировании старого отзыва требуется выбрать оценку.
13. При отсутствии оценок страница курса показывает «Оценок пока нет».
14. Ограничение PostgreSQL не допускает значений вне диапазона `1..5`.

## 10. План тестирования

### 10.1. Form и Service

- валидные значения `1` и `5`;
- `NULL`, `0`, `6`, дробное и нечисловое значение;
- сохранение оценки при создании;
- изменение оценки собственного отзыва;
- отказ при изменении чужого отзыва;
- обновление `lastUpdate`;
- корректная работа с legacy-отзывом без оценки.

### 10.2. Repository

- среднее для нескольких оценок;
- количество учитывает только ненулевые оценки;
- отзыв с `NULL` не искажает среднее;
- отсутствие оценок возвращает пустое среднее и нулевое количество;
- SQL `CHECK` отклоняет значения вне диапазона.

### 10.3. Controller и UI

- повторный показ формы при невалидной оценке;
- сохранение выбранного значения после ошибки;
- redirect после успешного создания и редактирования;
- отображение индивидуальной и средней оценки;
- сценарии владельца, другого пользователя и гостя;
- работа формы без JavaScript.

## 11. Последовательность реализации

1. Проверить существующие значения `feedback.rating`.
2. Добавить SQL-миграцию с `CHECK`.
3. Согласовать JPA-модель с колонкой.
4. Расширить `FeedbackForm` и серверную валидацию.
5. Обновить создание и редактирование отзыва.
6. Добавить агрегатный запрос и DTO результата.
7. Обновить формы и отображение отзывов.
8. Добавить средний рейтинг на страницу курса.
9. Реализовать автоматические тесты.
10. Выполнить сборку и сквозную проверку через Tomcat.

## 12. Не входит в задачу

- половинчатые оценки и шкалы, отличные от `1..5`;
- рейтинг без текстового отзыва;
- отдельная сущность оценки;
- сохранённое поле среднего рейтинга в `course`;
- сортировка и фильтрация каталога по рейтингу;
- модерация оценок;
- изменение правила «один пользователь — один отзыв на курс»;
- автоматическое назначение рейтинга старым отзывам.

## 13. Риски

| Риск | Мера снижения |
|---|---|
| В базе есть значения вне диапазона | диагностический запрос и остановка миграции |
| Старые отзывы имеют `NULL` | nullable `Integer`, явное состояние «Без оценки» |
| Среднее рассинхронизируется с отзывами | вычисление агрегата запросом, без хранения в `course` |
| Клиент подставляет произвольное значение | DTO-валидация, проверка сервиса и SQL `CHECK` |
| Изменение оценки чужого отзыва | загрузка по `feedbackId + currentProfileId` |
| N+1 при отображении списка | агрегатный запрос и существующая загрузка отзывов |

## 14. Условия готовности

Задача считается завершённой, когда выполнены критерии приёмки, SQL и JPA согласованы, применимые тесты пройдены, сборка `mvn package -DskipTests` успешна, а через Tomcat проверены создание, изменение, удаление, legacy-отзыв и попытка изменения чужой оценки.
